# 요청은 실측과 같은 모양으로 보낸다

`acceptance-criteria.md`의 실측과 같은 층에서, 같은 경로와 같은 필드 집합으로 보낸다.
실측에 없던 필드를 테스트가 새로 만들거나, 실측이 채운 필드를 빼지 않는다.

이유 — 인수 조건의 예시가 curl로 적혀 있다. 테스트가 그것과 다른 요청을 보내기 시작하면
테스트는 통과하는데 실제 호출은 실패하는 자리가 생긴다.

# 프로덕션 타입을 쓰지 않는다

인수 테스트는 요청을 맵으로 만들고, 응답을 필드 이름으로 읽는다.

이유 — 인수 테스트는 그 움직임이 겉보기 행동을 바꿨는지 판정하는 쪽이어야 한다.
프로덕션 타입을 함께 쓰면 타입이 바뀔 때 테스트도 따라 바뀌어, 행동이 그대로인지 판정할 수 없다.

# 거절 뒤 상태까지 단언한다

상태 코드와 메시지 전문에 더해,
남지 않아야 할 것이 남지 않았는지 바뀌지 않아야 할 것이 그대로인지를 조회로 본다.

이유 — 상태 코드만 보면 거절해 놓고 저장하는 경우를 놓친다.

# 호출과 단언을 나눈다

공통 호출부는 요청만 보내고 응답을 그대로 돌려준다. 무엇을 통과로 볼지는 각 테스트가 정한다.

이유 — 호출 쪽이 상태 코드를 단언하면 티켓마다 다른 통과 기준을 걸 수 없다.
