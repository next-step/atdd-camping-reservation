## 1. 예약 생성

### 1.1 정상 예약 생성

**핵심 인수 조건**: "고객이 예약 가능한 사이트를 선택하면 예약이 생성되고, 6자리 확인 코드가 발급된다."

#### 시나리오
```gherkin
Given A-1 사이트가 2026년 2월 1일부터 2월 3일까지 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 2026년 2월 1일부터 2월 3일까지 예약하면
Then 예약이 성공적으로 생성되고
And 6자리 확인 코드가 발급되고
And 예약 상태가 "CONFIRMED"로 설정된다.
```

#### 검증 포인트
- [x] 201 Created 응답
- [x] 6자리 확인 코드 발급
- [x] 예약 상태 = CONFIRMED

---

### 1.2 중복 예약 방지

**핵심 인수 조건**: "같은 사이트의 예약 기간이 1일이라도 겹치면 예약이 거부된다."

#### 시나리오
```gherkin
Given A-1 사이트가 2026년 2월 1일부터 2월 3일까지 홍길동에게 예약되어 있고
When 김철수가 A-1 사이트를 2026년 2월 2일부터 2월 4일까지 예약 시도하면
Then 예약이 거부된다.
```

#### 검증 포인트
- [x] 409 Conflict 응답
- [x] 기간 겹침 검증

---

### 1.3 동시 예약 제어

**핵심 인수 조건**: "동시에 같은 사이트/날짜로 예약 요청이 들어오면 한 건만 성공한다."

#### 시나리오
```gherkin
Given A-1 사이트가 2026년 2월 1일에 예약 가능한 상태이고
When 홍길동과 김철수가 동시에 같은 날짜로 A-1 사이트 예약을 요청하면
Then 한 명의 예약만 성공하고
And 나머지 한 명은 예약이 거부된다.
```

#### 검증 포인트
- [x] CountDownLatch로 동시성 테스트
- [x] 1개 201, 1개 409 응답

---

### 1.4 예약 기간 제한 (30일)

**핵심 인수 조건**: "예약 기간은 최대 30일까지만 가능하다."

#### 시나리오 A - 30일 초과
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 2026-02-01부터 2026-03-05까지 (32일) 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 시나리오 B - 정확히 30일
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 2026-02-01부터 2026-03-02까지 (30일) 예약하면
Then 예약이 생성된다.
```

#### 검증 포인트
- [x] 31일 이상 → 409
- [x] 정확히 30일 → 201

### 1.5 인원수 검증

**핵심 인수 조건**: "예약 인원은 1명 이상, 사이트 최대 인원 이하여야 한다."

#### 시나리오 A - 0명

Given A-1 사이트가 예약 가능한 상태이고

Given A-1 사이트의 최대 수용 인원은 6명이고
When 홍길동이 A-1 사이트를 7명으로 예약 시도하면
Then 예약은 생성되지 않는다.

#### 시나리오 C - 최대 인원과 동일
```gherkin
Given A-1 사이트의 최대 수용 인원은 6명이고
When 홍길동이 A-1 사이트를 6명으로 예약하면
Then 예약이 생성된다.
```

#### 검증 포인트
- [x] 0명 → 409
- [x] 7명 (최대 6명) → 409
- [x] 6명 → 201

### 1.6 날짜 유효성 검증

**핵심 인수 조건**: "과거 날짜 예약 불가, 종료일은 시작일 이후여야 한다."

#### 시나리오 A - 과거 날짜
```gherkin
Given 오늘 날짜 기준으로 과거 날짜이고
When 홍길동이 A-1 사이트를 과거 날짜로 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 시나리오 B - 날짜 역전
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 시작일 2026-02-05, 종료일 2026-02-03으로 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 검증 포인트
- [x] 과거 날짜 → 409
- [x] 종료일 < 시작일 → 409

### 1.7 예약 경계값 테스트

**핵심 인수 조건**: "예약 종료일과 다음 예약 시작일이 같으면 중복으로 거부된다."

#### 시나리오 A - 종료일 = 시작일 (거부)
```gherkin
Given 홍길동이 A-1 사이트를 2026-02-01부터 2026-02-03까지 예약했고
When 김철수가 A-1 사이트를 2026-02-03부터 2026-02-05까지 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 시나리오 B - 종료일 + 1일 = 시작일 (성공)
```gherkin
Given 홍길동이 A-1 사이트를 2026-02-01부터 2026-02-03까지 예약했고
When 김철수가 A-1 사이트를 2026-02-04부터 2026-02-06까지 예약하면
Then 예약이 생성된다.
```

#### 시나리오 C - 시작일 포함 (거부)
```gherkin
Given 홍길동이 A-1 사이트를 2026-02-01부터 2026-02-03까지 예약했고
When 김철수가 A-1 사이트를 2026-02-01부터 2026-02-02까지 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 시나리오 D - 종료일 포함 (거부)
```gherkin
Given 홍길동이 A-1 사이트를 2026-02-01부터 2026-02-03까지 예약했고
When 김철수가 A-1 사이트를 2026-02-02부터 2026-02-03까지 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 시나리오 E - 완전히 포함 (거부)
```gherkin
Given 홍길동이 A-1 사이트를 2026-02-02부터 2026-02-03까지 예약했고
When 김철수가 A-1 사이트를 2026-02-01부터 2026-02-04까지 예약 시도하면
Then 예약은 생성되지 않는다.
```

#### 검증 포인트
- [x] 종료일 = 시작일 → 409
- [x] 종료일 + 1일 = 시작일 → 201
- [x] 시작일 포함 → 409
- [x] 종료일 포함 → 409
- [x] 완전히 포함 → 409

## 2. 예약 수정

### 2.1 정상 예약 수정

**핵심 인수 조건**: "올바른 확인 코드로 예약 날짜를 변경할 수 있으며, 확인 코드는 유지된다."

#### 시나리오
```gherkin
Given 홍길동이 A-1 사이트를 2026년 2월 1일~3일로 예약을 하고
When 홍길동이 확인 코드를 입력하고 날짜를 2월 5일~7일로 변경하면
Then 예약 날짜가 2월 5일~7일로 수정되고
And 기존 확인 코드는 유지된다.
```

#### 검증 포인트
- [x] 200 OK 응답
- [x] 날짜 변경 반영
- [x] 확인 코드 유지

---

### 2.2 잘못된 확인 코드로 수정 시도

**핵심 인수 조건**: "틀린 확인 코드로는 예약을 수정할 수 없다."

#### 시나리오
```gherkin
Given A-1 사이트가 2026년 2월 1일부터 2월 3일까지 홍길동에게 예약되어 있고
When 틀린 확인 코드를 입력하고 예약 수정을 시도하면
Then 예약이 거부된다.
```

#### 검증 포인트
- [x] 400 Bad Request 응답

---

### 2.3 다른 예약과 충돌하는 날짜로 수정

**핵심 인수 조건**: "이미 예약된 날짜로는 예약을 수정할 수 없다."

#### 시나리오
```gherkin
Given 홍길동이 A-1 사이트를 2월 1일~3일로 예약했고

When 홍길동이 자신의 예약을 2월 5일~7일로 변경 시도하면
Then 수정이 거부된다.
```

#### 검증 포인트
- [x] 400 Bad Request 응답
- [x] 다른 예약과 충돌 검사

## 3. 예약 취소

### 3.1 정상 예약 취소 (사전 취소)

**핵심 인수 조건**: "올바른 확인 코드로 예약을 취소하면 사이트가 즉시 예약 가능 상태가 된다."

#### 시나리오
```gherkin
Given 홍길동이 A-1 사이트를 2026년 2월 5일~7일로 예약했고
When 홍길동이 올바른 확인 코드로 예약 취소를 요청하면
Then 예약이 취소되고
And A-1 사이트가 2월 5일~7일에 예약 가능해지고
And 예약 상태가 '사전 취소' 상태로 변경된다.
```

#### 검증 포인트
- [x] 200 OK 응답
- [x] 상태 = CANCELLED
- [x] 사이트 예약 가능 상태 복구

---

### 3.2 당일 취소

**핵심 인수 조건**: "예약 시작일 당일에 취소하면 '당일 취소' 상태로 변경된다."

#### 시나리오
```gherkin
Given 홍길동이 A-1 사이트를 2026년 2월 1일~3일로 예약했고
And 오늘 날짜는 2026년 2월 1일이다 (예약 시작일)
When 홍길동이 올바른 확인 코드로 예약 취소를 요청하면
Then 예약이 취소되고
And 예약 상태가 '당일 취소' 상태로 변경된다.
```

#### 검증 포인트
- [x] 200 OK 응답
- [x] 상태 = CANCELLED_SAME_DAY
- [x] 당일 취소 구분

---

### 3.3 잘못된 확인 코드로 취소 시도

**핵심 인수 조건**: "틀린 확인 코드로는 예약을 취소할 수 없다."

## 4. 예약 금액 계산

### 4.1 기본 요금

**핵심 인수 조건**: "A 사이트(대형)의 기본 요금은 80,000원이다."

#### 시나리오
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 비수기 평일 1박으로 예약하면
Then 예약 금액은 80,000원이다.
```

#### 검증 포인트
- [x] 기본 요금 = 80,000원

---

### 4.2 주말 할증

**핵심 인수 조건**: "주말(토요일)에는 30% 할증이 적용된다."

#### 시나리오
```gherkin
Given A-1 사이트가 예약 가능한 상태이고

```

#### 검증 포인트
- [x] 주말 할증 = 30%
- [x] 104,000원

---

### 4.3 성수기 할증

**핵심 인수 조건**: "성수기(7~8월) 평일은 50%, 주말은 70% 할증이 적용된다."

#### 시나리오 A - 성수기 평일
```gherkin
Given A-1 사이트가 예약 가능한 상태이고

Then 예약 금액은 120,000원이다. (80,000 * 1.5)
```

#### 시나리오 B - 성수기 주말
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 8월 토요일 1박으로 예약하면
Then 예약 금액은 136,000원이다. (80,000 * 1.7)
```

#### 검증 포인트
- [x] 성수기 평일 할증 = 50%
- [x] 성수기 주말 할증 = 70%

---

### 4.4 복합 요금 계산

**핵심 인수 조건**: "여러 날짜 예약 시 각 날짜별 요금을 합산한다."

#### 시나리오 A - 평일 2박
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 비수기 월요일부터 수요일까지 2박으로 예약하면
Then 예약 금액은 160,000원이다. (80,000 * 2)
```

#### 시나리오 B - 평일+주말 혼합
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 비수기 금요일부터 일요일까지 2박으로 예약하면
Then 예약 금액은 184,000원이다. (금요일 80,000 + 토요일 104,000)
```

#### 시나리오 C - 비수기+성수기 혼합
```gherkin
Given A-1 사이트가 예약 가능한 상태이고
When 홍길동이 A-1 사이트를 6월 30일부터 7월 2일까지 2박으로 예약하면
Then 예약 금액은 200,000원이다. (6월 30일 80,000 + 7월 1일 120,000)
```

#### 검증 포인트
- [x] 일별 요금 합산
- [x] 평일+주말 혼합 계산
- [x] 비수기+성수기 혼합 계산

#### 시나리오 C - 성수기 종료일 (8/31)

Given A-1 사이트가 예약 가능한 상태이고

#### 시나리오 D - 성수기 다음날 (9/1)
