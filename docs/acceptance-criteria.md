# 인수 조건

## T-1 예약 가능 날짜 범위

### 규칙과 범위

- 신규 예약의 시작일은 오늘부터 30일 이내여야 한다.
- 시작일이 오늘부터 31일 이상 남았으면 예약을 저장하지 않고 HTTP 409와 `예약 시작일은 오늘로부터 30일 이내여야 합니다.`를 응답한다.
- 이 조건은 `POST /api/reservations`에 적용한다.
- 고객센터에서 30일을 초과해 남은 날짜도 예약된다는 신고가 접수되어 시작일의 허용 범위를 제한한다.

### 시나리오

#### 30일째 예약

- Given 오늘이 2026-08-18이고 나머지 예약 정보가 유효하다.
- When 시작일이 2026-09-17인 예약을 생성한다.
- Then HTTP 201을 응답하고 예약을 저장한다.

#### 31일째 예약

- Given 오늘이 2026-08-18이고 나머지 예약 정보가 유효하다.
- When 시작일이 2026-09-18인 예약을 생성한다.
- Then HTTP 409와 `예약 시작일은 오늘로부터 30일 이내여야 합니다.`를 응답하고 예약을 저장하지 않는다.

### 변경 전 실측 요약

- 실측 기준일: 2026-08-18 (Asia/Seoul)

| 경계       | 시작일        | 실제 결과         | 기대 결과            | 판정  |
|----------|------------|---------------|------------------|-----|
| 오늘부터 30일 | 2026-09-17 | HTTP 201, 저장됨 | HTTP 201, 저장됨    | 일치  |
| 오늘부터 31일 | 2026-09-18 | HTTP 201, 저장됨 | HTTP 409, 저장 안 됨 | 불일치 |

## T-2 신규 예약 전화번호 조건

### 규칙과 범위

- 신규 예약의 전화번호는 필수다.
- 전화번호가 누락되거나 `null`, 빈 문자열, 공백 문자열이면 예약을 저장하지 않고 HTTP 400과 `전화번호를 입력해주세요.`를 응답한다.
- 이번 조건은 필수 여부만 추가하며, 신규 예약 코드가 기존부터 강제하던 형식 검증은 변경하지 않는다. 형식 정책은 T-8에서 별도로 정한다.
- 이 조건은 `POST /api/reservations`에 적용한다.
- 고객센터에서 전화번호가 없는 예약도 생성된다는 신고가 접수되어 필수 여부를 명시한다.

### 시나리오

#### 전화번호가 없는 예약

- Given 전화번호를 제외한 예약 정보가 유효하다.
- When 전화번호를 누락하거나 `null`, 빈 문자열 또는 공백 문자열로 예약을 생성한다.
- Then HTTP 400과 `전화번호를 입력해주세요.`를 응답하고 예약을 저장하지 않는다.

#### 기존 형식 검증을 통과하는 전화번호가 있는 예약

- Given 전화번호를 제외한 예약 정보가 유효하다.
- When 기존 형식 검증을 통과하는 비어 있지 않은 전화번호로 예약을 생성한다.
- Then HTTP 201을 응답하고 요청한 전화번호를 저장한다.

### 변경 전 실측 요약

- 실측 기준일: 2026-08-19 (Asia/Seoul)

| 경계           | 입력                        | 실제 결과                 | 기대 결과            | 판정  |
|--------------|---------------------------|-----------------------|------------------|-----|
| 필수 조건 위반     | 누락, `null`, 빈 문자열, 공백 문자열 | HTTP 201, 입력값 그대로 저장됨 | HTTP 400, 저장 안 됨 | 불일치 |
| 기존 형식 통과 대표값 | `12345678910`             | HTTP 201, 저장됨         | HTTP 201, 저장됨    | 일치  |

## T-3 예약 변경 전화번호 조건

### 규칙과 범위

- 예약 변경에서도 전화번호는 필수다.
- 전화번호는 정규식 `^010(?:-\d{4}-\d{4}|\d{8})$`에 맞는 `010-0000-0000` 또는 `01000000000` 형식이어야 한다.
- 전화번호가 누락되거나 `null`, 빈 문자열, 공백 문자열이면 HTTP 400과 `전화번호를 입력해주세요.`를 응답한다.
- 허용된 형식이 아니면 HTTP 400과 `유효한 전화번호가 아닙니다.`를 응답한다.
- 거부된 요청은 기존 전화번호를 포함한 예약 정보를 변경하지 않는다.
- 허용된 전화번호이면 HTTP 200을 응답하고 요청한 전화번호를 저장한다.
- 이 조건은 `PUT /api/reservations/{id}`에 적용하며, 신규 예약의 조건은 T-2에서 다룬다.
- 예약 변경으로 필수 전화번호를 제거하거나 허용하지 않은 형식으로 바꾸는 경로를 막는다.

### 시나리오

#### 전화번호가 없는 변경

- Given 전화번호가 `010-1111-2222`인 예약이 있다.
- When 전화번호를 누락하거나 `null`, 빈 문자열 또는 공백 문자열로 변경한다.
- Then HTTP 400과 `전화번호를 입력해주세요.`를 응답하고 기존 예약 정보를 유지한다.

#### 허용되지 않은 전화번호로 변경

- Given 전화번호가 `010-1111-2222`인 예약이 있다.
- When 허용된 두 형식과 다른 전화번호로 변경한다.
- Then HTTP 400과 `유효한 전화번호가 아닙니다.`를 응답하고 기존 예약 정보를 유지한다.

#### 허용된 전화번호로 변경

- Given 전화번호가 `010-1111-2222`인 예약이 있다.
- When `010-2222-3333` 또는 `01022223333`으로 변경한다.
- Then HTTP 200을 응답하고 요청한 전화번호를 저장한다.

### 변경 전 실측 요약

- 실측 기준일: 2026-08-21 (Asia/Seoul)
- 각 경계는 서로 다른 사이트에 유효한 전화번호 `010-1111-2222`로 기준 예약을 만든 뒤 측정했다.

| 경계 | 입력 | 실제 결과 | 변경 후 저장 상태 | 기대 결과 | 판정 |
|---|---|---|---|---|---|
| 필수 조건 위반 | 누락, `null` | HTTP 200 | 기존 번호 유지 | HTTP 400, 기존 정보 유지 | 불일치 |
| 필수 조건 위반 | 빈 문자열, 공백 문자열 | HTTP 200 | 입력값 저장 | HTTP 400, 기존 정보 유지 | 불일치 |
| 형식 조건 위반 | 잘못된 접두사, 하이픈, 자릿수 또는 문자 포함 | HTTP 200 | 입력값 저장 | HTTP 400, 기존 정보 유지 | 불일치 |
| 하이픈 형식 | `010-2222-3333` | HTTP 200 | 요청한 번호 저장 | HTTP 200, 요청한 번호 저장 | 일치 |
| 숫자만 형식 | `01022223333` | HTTP 200 | 요청한 번호 저장 | HTTP 200, 요청한 번호 저장 | 일치 |

## T-4 취소한 예약 자리의 재예약

### 규칙과 범위

- 신규 예약과 같은 사이트에서 기간이 겹치는 `CONFIRMED` 예약이 있으면 새 예약을 저장하지 않고 HTTP 409와 `해당 기간에 이미 예약이 존재합니다.`를 응답한다.
- T-4에서는 신규 예약과 사이트·시작일·종료일이 모두 같은 `CANCELLED` 또는 `CANCELLED_SAME_DAY` 예약을 기간 충돌에서 제외한다.
- 재예약에 성공하면 기존 취소 예약은 이력으로 유지하고 별도의 `CONFIRMED` 예약을 저장한다.
- 이 조건은 `POST /api/reservations`의 사이트·기간 중복 판단에 적용한다.
- 일부 날짜만 겹치는 취소 예약, 예약 가능 여부 조회, 캘린더 조회와 예약 변경은 T-4 범위에 포함하지 않는다.
- 고객센터에서 취소한 예약과 같은 날짜의 같은 자리를 다시 예약할 수 없다는 신고가 접수되어 취소 예약의 충돌 판단을 변경한다.

### 시나리오

#### 확정 예약과 같은 자리

- Given 특정 사이트와 기간에 `CONFIRMED` 예약이 있다.
- When 같은 사이트와 같은 기간으로 신규 예약을 생성한다.
- Then HTTP 409와 `해당 기간에 이미 예약이 존재합니다.`를 응답하고 새 예약을 저장하지 않는다.

#### 일반 취소 후 같은 자리

- Given 특정 사이트와 기간의 예약을 취소하여 상태가 `CANCELLED`다.
- When 같은 사이트와 같은 기간으로 신규 예약을 생성한다.
- Then HTTP 201을 응답하고 별도의 `CONFIRMED` 예약을 저장한다.
- And 기존 `CANCELLED` 예약은 유지한다.

#### 당일 취소 후 같은 자리

- Given 오늘 시작하는 예약을 취소하여 상태가 `CANCELLED_SAME_DAY`다.
- When 같은 사이트와 같은 기간으로 신규 예약을 생성한다.
- Then HTTP 201을 응답하고 별도의 `CONFIRMED` 예약을 저장한다.
- And 기존 `CANCELLED_SAME_DAY` 예약은 유지한다.

### 변경 전 실측 요약

- 실측 기준일: 2026-08-21 (Asia/Seoul)

| 경계 | 기존 상태 | 실제 결과 | 저장 상태 | 기대 결과 | 판정 |
|---|---|---|---|---|---|
| 확정 예약과 같은 자리·기간 | `CONFIRMED` | HTTP 409 | 기존 예약만 유지 | HTTP 409, 새 예약 없음 | 일치 |
| 일반 취소와 같은 자리·기간 | `CANCELLED` | HTTP 409 | 취소 예약만 유지 | HTTP 201, 취소 이력과 새 예약 유지 | 불일치 |
| 당일 취소와 같은 자리·기간 | `CANCELLED_SAME_DAY` | HTTP 409 | 취소 예약만 유지 | HTTP 201, 취소 이력과 새 예약 유지 | 불일치 |

### 후속 범위

- T-5: 취소된 다일 예약과 일부 날짜만 겹치는 신규 예약도 허용할지 별도로 결정하고 실측한다.
- T-6: 예약 가능 여부와 캘린더가 `CANCELLED`, `CANCELLED_SAME_DAY` 예약을 빈자리로 표시하는지 조회 경로별로 확인한다.
