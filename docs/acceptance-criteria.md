# Top 3 인수 조건

## 1. 예약 생성 (리스크 9점)

**인수 조건**: "고객이 유효한 날짜와 사이트 정보를 입력하면, 중복 예약이 없는 경우 예약이 생성되고 확인 코드가 발급된다."

**검증 포인트** (API 응답 기반):

정상 케이스:
- [ ] 유효한 정보로 예약 시 201 응답
- [ ] 응답에 status: "CONFIRMED" 포함
- [ ] 응답에 6자리 confirmationCode 포함

입력 검증:
- [ ] 사이트번호 없음/존재하지 않는 사이트 → 4xx 응답
- [ ] 과거 날짜 → 4xx 응답
- [ ] 종료일 < 시작일 → 4xx 응답
- [ ] 30일 초과 → 4xx 응답
- [ ] 이름 2자 미만/20자 초과 → 4xx 응답
- [ ] 전화번호 형식 오류 (10~11자리 아님) → 4xx 응답

중복 예약 방지:
- [ ] 동일 사이트 겹치는 기간 → 4xx 응답

## 2. 예약 취소 (리스크 7점)

**인수 조건**: "고객이 올바른 확인 코드와 함께 취소를 요청하면, 예약 상태가 취소로 변경되고 취소 시점에 따라 적절한 상태값이 설정된다."

**검증 포인트** (API 응답 기반):

정상 케이스:
- [ ] 올바른 확인코드로 취소 시 200 응답
- [ ] 체크인 이전 취소 → 조회 시 status: "CANCELLED"
- [ ] 체크인 당일 취소 → 조회 시 status: "CANCELLED_SAME_DAY"

예외 케이스:
- [ ] 존재하지 않는 예약 ID → 404 응답
- [ ] 잘못된 확인코드 → 4xx 응답

## 3. 예약 수정 (리스크 7점)

**인수 조건**: "고객이 올바른 확인 코드와 함께 유효한 변경 정보를 요청하면, 예약 정보가 업데이트되고 중복 예약이 발생하지 않는다."

**검증 포인트** (API 응답 기반):

정상 케이스:
- [ ] 올바른 확인코드로 수정 시 200 응답
- [ ] 응답에 변경된 정보 반영
- [ ] 수정 후 조회 시 변경 내용 확인

예외 케이스:
- [ ] 존재하지 않는 예약 ID → 404 응답
- [ ] 잘못된 확인코드 → 4xx 응답
- [ ] 과거 날짜로 변경 → 4xx 응답
- [ ] 30일 초과 기간으로 변경 → 4xx 응답
- [ ] 변경된 날짜/사이트로 중복 발생 → 4xx 응답
