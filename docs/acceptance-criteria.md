# 인수 조건

> risk-matrix.md 기반 우선순위 정렬

---

## 1. 예약 생성 (9점)

**고객이 예약 API로 캠핑 사이트를 예약한다 (오늘~30일 이내)**

| 항목 | 내용 |
|------|------|
| **What** | 캠핑 사이트 예약 생성 |
| **Who** | 캠핑장을 이용하려는 고객 |
| **When** | 오늘로부터 30일 이내의 미래 날짜 |
| **Where** | 예약 가능한 캠핑 사이트 |
| **Why** | 원하는 날짜에 캠핑장을 이용하기 위해 |
| **How** | 예약자 정보와 희망 날짜를 입력하여 예약 확정 |

**인수 조건**: 고객이 유효한 정보로 예약 요청 시, 중복 없이 예약이 생성되고 6자리 확인코드가 발급되어야 한다.

**검증 포인트**
- [ ] 과거 날짜 예약 거부
- [ ] 종료일 < 시작일 거부
- [ ] 오늘로부터 30일 초과 시작일 거부
- [ ] 이름 2~20자 검증
- [ ] 전화번호 10~11자리 검증
- [ ] 존재하지 않는 사이트 거부
- [ ] 동일 사이트/기간 중복 예약 거부
- [ ] 취소된 예약은 중복 체크 제외
- [ ] 6자리 영숫자 확인코드 생성
- [ ] 성공 시 201 응답 + 예약정보 반환

**경계값 검증**
- [ ] 이름 2자 허용, 1자 거부
- [ ] 이름 20자 허용, 21자 거부
- [ ] 전화번호 10자리 허용, 9자리 거부
- [ ] 시작일 = 오늘 허용, 어제 거부
- [ ] 시작일 = 오늘+30일 허용, 오늘+31일 거부

## 2. 가용성 확인 (8점)

**고객이 예약 전 가용 사이트를 조회한다**

| 항목 | 내용 |
|------|------|
| **What** | 특정 날짜/기간에 예약 가능한 사이트 조회 |
| **Who** | 예약을 원하는 고객 |
| **When** | 예약 전 사전 확인 시점 |
| **Where** | 전체 사이트 또는 특정 사이트 |
| **Why** | 예약 가능 여부를 미리 확인하기 위해 |
| **How** | 날짜를 입력하면 예약 가능한 사이트 목록 반환 |

**인수 조건**: 조회 시점에 실제 예약 가능한 사이트만 정확하게 반환되어야 한다.

**검증 포인트**
- [ ] 예약된 사이트는 가용 목록에서 제외
- [ ] 취소된 예약의 사이트는 가용으로 표시
- [ ] 단일 날짜/기간 검색 결과 일치
- [ ] 사이즈 필터(대형/소형) 정상 동작
- [ ] 과거 날짜 조회 거부

**경계값 검증**
- [ ] 조회일 = 오늘 허용, 어제 거부
- [ ] 예약 시작일 당일 조회 시 해당 사이트 제외

---

## 3. 연박 예약 (7점)

**고객이 2박 이상 연속 예약한다**

| 항목 | 내용 |
|------|------|
| **What** | 2박 이상 연속된 기간에 대한 예약 |
| **Who** | 장기 캠핑을 원하는 고객 |
| **When** | 시작일부터 종료일까지 연속된 모든 날짜 |
| **Where** | 전체 기간 동안 예약 가능한 사이트 |
| **Why** | 여러 날 연속으로 캠핑장을 이용하기 위해 |
| **How** | 시작일과 종료일 지정, 전체 기간 가용 시 예약 확정 |

**인수 조건**: 연박 예약 시 시작일부터 종료일까지 모든 날짜가 예약 가능해야만 예약이 성공한다.

**검증 포인트**
- [ ] 중간 날짜에 기존 예약 있으면 거부
- [ ] 시작일/종료일만 비어있어도 중간 날짜 점유 시 거부
- [ ] 검색 API도 전체 기간 가용 사이트만 반환
- [ ] 3박 예약 시 4일치 모두 검증

**경계값 검증**
- [ ] 1박(시작일=종료일-1) 허용
- [ ] 30박(최대) 허용, 31박 거부
- [ ] 2박 예약 시 3일치 모두 검증

## 4. 예약 취소 (6점)

**고객이 확인코드로 본인 예약을 취소한다**

| 항목 | 내용 |
|------|------|
| **What** | 기존 예약 취소 |
| **Who** | 예약한 고객 |
| **When** | 예약 후 취소가 필요할 때 |
| **Where** | 본인이 예약한 건에 대해 |
| **Why** | 일정 변경 등으로 예약 이용이 불가할 때 |
| **How** | 확인코드로 본인 확인 후 취소 처리 |

**인수 조건**: 본인 확인(확인코드) 후에만 예약 취소가 가능하며, 취소 시점에 따라 상태가 구분되어야 한다.

**검증 포인트**
- [ ] 확인코드 불일치 시 취소 거부
- [ ] 당일 취소 시 CANCELLED_SAME_DAY 상태
- [ ] 사전 취소 시 CANCELLED 상태
- [ ] 취소된 사이트는 즉시 재예약 가능

**경계값 검증**
- [ ] 시작일 당일 취소 → CANCELLED_SAME_DAY
- [ ] 시작일 전날 취소 → CANCELLED

## 5. 동시성 제어 (6점)

**다수 고객이 동일 사이트를 동시에 예약 시도한다**

| 항목 | 내용 |
|------|------|
| **What** | 동시 예약 요청에 대한 제어 |
| **Who** | 동시에 예약을 시도하는 다수의 고객 |
| **When** | 같은 시점에 동일 사이트/기간 예약 시도 시 |
| **Where** | 동일한 사이트와 날짜 |
| **Why** | 중복 예약 방지 |
| **How** | 락/트랜잭션으로 단 하나의 예약만 성공 |

**인수 조건**: 동일 사이트/기간에 동시 예약 요청이 들어와도 단 하나의 예약만 성공해야 한다.

**검증 포인트**
- [ ] 동시 10건 요청 시 1건만 성공
- [ ] 나머지는 충돌 에러 반환
- [ ] 성공한 예약 데이터 정합성 유지

---

## 6. 예약 수정 (6점)

**고객이 확인코드로 본인 예약을 수정한다**

| 항목 | 내용 |
|------|------|
| **What** | 기존 예약 정보 수정 |
| **Who** | 예약한 고객 |
| **When** | 예약 후 변경이 필요할 때 |
| **Where** | 본인이 예약한 건에 대해 |
| **Why** | 날짜/사이트 변경이 필요할 때 |
| **How** | 확인코드로 본인 확인 후 수정 처리 |

**인수 조건**: 본인 확인 후 수정 시, 변경된 날짜/사이트에 대해 중복 검사가 수행되어야 한다.

**검증 포인트**
- [ ] 확인코드 불일치 시 수정 거부
- [ ] 날짜 변경 시 중복 검사 수행
- [ ] 사이트 변경 시 중복 검사 수행
- [ ] 수정 성공 시 변경된 정보 반환
