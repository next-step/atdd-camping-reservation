## 1. 예약 생성

### 5W1H 분석

| 항목 | 내용 |
|------|------|
| **What** (무엇을) | 캠핑 사이트 예약을 생성하는 기능 |
| **Who** (누가) | 캠핑장을 이용하려는 고객 |
| **When** (언제) | 오늘로부터 30일 이내의 미래 날짜에 대해 |
| **Where** (어디서) | 예약 가능한 캠핑 사이트에 대해 |
| **Why** (왜) | 원하는 날짜에 캠핑장을 이용하기 위해 |
| **How** (어떻게) | 예약자 정보와 희망 날짜를 입력하여 예약을 확정하고 확인 코드를 발급받음 |

### 인수 조건

**"고객이 유효한 정보로 예약 요청 시, 중복되지 않은 사이트에 대해 예약이 생성되고 6자리 확인 코드가 발급되어야 한다."**

### 검증 포인트

#### 필수 입력값 검증
- [ ] 예약자 이름이 없으면 예약 실패 (에러: "예약자 이름을 입력해주세요.")
- [ ] 예약자 이름이 2자 미만이면 예약 실패 (에러: "예약자 이름은 최소 2자 이상이어야 합니다.")
- [ ] 예약자 이름이 20자 초과면 예약 실패
- [ ] 사이트 번호가 없으면 예약 실패 (에러: "사이트 번호를 입력해주세요.")
- [ ] 존재하지 않는 사이트 번호면 예약 실패 (에러: "존재하지 않는 캠핑장입니다.")
- [ ] 시작일 또는 종료일이 없으면 예약 실패 (에러: "예약 기간을 선택해주세요.")

#### 날짜 검증
- [ ] 시작일이 과거 날짜면 예약 실패 (에러: "과거 날짜로 예약할 수 없습니다.")
- [ ] 종료일이 시작일보다 이전이면 예약 실패 (에러: "종료일이 시작일보다 이전일 수 없습니다.")
- [ ] 예약 기간이 30일 초과면 예약 실패 (에러: "예약 기간은 최대 30일입니다.")
- [ ] **[버그]** 오늘로부터 30일 이후 시작일도 예약 가능한지 확인 필요

#### 전화번호 검증
- [ ] 전화번호가 10자리 미만이면 예약 실패 (에러: "전화번호 형식이 올바르지 않습니다.")
- [ ] 전화번호가 11자리 초과면 예약 실패
- [ ] 전화번호에 숫자 외 문자가 포함되면 예약 실패 (에러: "전화번호는 숫자만 입력 가능합니다.")
- [ ] 하이픈(-)은 자동 제거 후 검증

#### 중복 예약 검증
- [ ] 동일 사이트, 동일 기간에 기존 예약이 있으면 실패 (에러: "해당 기간에 이미 예약이 존재합니다.")
- [ ] **[버그]** 취소된 예약(CANCELLED)은 중복 체크에서 제외되어야 함
- [ ] 기간이 겹치는 경우 (기존: 1/5~1/7, 신규: 1/6~1/8) 예약 실패

#### 예약 성공 시
- [ ] 6자리 영숫자 확인 코드가 생성됨
- [ ] 예약 상태가 "CONFIRMED"로 설정됨
- [ ] 생성 시간(createdAt)이 자동 기록됨
- [ ] 응답에 예약 ID, 확인 코드, 사이트 번호 등 필수 정보 포함

#### 가격 계산 검증
- [ ] 대형 사이트(A로 시작): 80,000원/박
- [ ] 소형 사이트(B로 시작): 50,000원/박
- [ ] 주말(토/일) 30% 할증 적용
- [ ] 성수기(7~8월) 50% 할증 적용
- [ ] 성수기 주말 70% 할증 적용

## 2. 연박 예약

### 5W1H 분석

| 항목 | 내용 |
|------|------|
| **What** (무엇을) | 2박 이상의 연속된 기간에 대한 캠핑 사이트 예약 |
| **Who** (누가) | 장기 캠핑을 원하는 고객 |
| **When** (언제) | 시작일부터 종료일까지 연속된 모든 날짜에 대해 |
| **Where** (어디서) | 전체 기간 동안 예약 가능한 사이트에 대해 |
| **Why** (왜) | 여러 날 연속으로 캠핑장을 이용하기 위해 |
| **How** (어떻게) | 시작일과 종료일을 지정하여 해당 기간 전체가 가용한 경우에만 예약 확정 |

### 인수 조건

**"연박 예약 시 시작일부터 종료일까지 모든 날짜가 예약 가능해야 하며, 중간에 하루라도 예약이 있으면 예약이 거부되어야 한다."**

### 검증 포인트

#### 전체 기간 가용성 검증
- [ ] 시작일만 예약 가능하고 중간 날짜에 예약이 있으면 실패해야 함
- [ ] 종료일만 예약 가능하고 중간 날짜에 예약이 있으면 실패해야 함
- [ ] **[Critical 버그]** 현재 코드는 시작일과 종료일만 검사함 - 중간 날짜 검증 필요

#### 경계값 테스트
- [ ] 1박 예약 (시작일 = 종료일의 전날): 정상 동작
- [ ] 2박 예약: 시작일, 중간일, 종료일 모두 검증
- [ ] 7박 예약: 전체 7일 모두 가용성 검증
- [ ] 30박 예약 (최대): 전체 기간 검증

#### 중복 시나리오 테스트
```
기존 예약: 1/10 ~ 1/12 (A1 사이트)

테스트 케이스:
- [ ] 1/8 ~ 1/9 예약 시도 → 성공 (겹치지 않음)
- [ ] 1/13 ~ 1/15 예약 시도 → 성공 (겹치지 않음)
- [ ] 1/9 ~ 1/11 예약 시도 → 실패 (1/10, 1/11 겹침)
- [ ] 1/11 ~ 1/14 예약 시도 → 실패 (1/11, 1/12 겹침)
- [ ] 1/8 ~ 1/14 예약 시도 → 실패 (1/10~1/12 겹침)
- [ ] 1/10 ~ 1/12 예약 시도 → 실패 (완전 동일)
```

#### 연박 가격 계산
- [ ] 각 날짜별 가격이 올바르게 합산됨
- [ ] 연박 중 일부만 주말인 경우 해당 날짜만 할증
- [ ] 연박 중 일부만 성수기인 경우 해당 날짜만 할증

#### 연박 검색 API 검증
- [ ] `/api/sites/search`에서 전체 기간 가용 사이트만 반환
- [ ] **[버그]** 현재는 시작일/종료일만 검사 - 중간 날짜 포함 검사 필요

## 3. 가용성 확인

### 5W1H 분석

| 항목 | 내용 |
|------|------|
| **What** (무엇을) | 특정 날짜 또는 기간에 예약 가능한 캠핑 사이트 조회 |
| **Who** (누가) | 예약을 원하는 고객 또는 관리자 |
| **When** (언제) | 예약 전 사전 확인 시점에 |
| **Where** (어디서) | 전체 사이트 또는 특정 사이트에 대해 |
| **Why** (왜) | 예약 가능 여부를 미리 확인하여 예약 실패를 방지하기 위해 |
| **How** (어떻게) | 날짜와 조건을 입력하면 예약 가능한 사이트 목록 또는 가용 여부를 반환 |

### 인수 조건

**"가용성 확인 결과가 '예약 가능'인 사이트에 대해 실제 예약 요청 시 반드시 성공해야 하며, 모든 API가 일관된 가용성 판단 기준을 사용해야 한다."**

### 검증 포인트

#### 단일 날짜 가용성 (`/api/sites/{siteNumber}/availability`)
- [ ] 예약이 없는 날짜 → available: true
- [ ] 예약이 있는 날짜 → available: false
- [ ] 취소된 예약이 있는 날짜 → available: true (취소된 건 제외)
- [ ] 과거 날짜 조회 시 에러 (에러: "과거 날짜는 조회할 수 없습니다.")
- [ ] 존재하지 않는 사이트 번호 시 에러

#### 가용 사이트 목록 (`/api/sites/available`)
- [ ] 해당 날짜에 예약 가능한 사이트만 반환
- [ ] **[버그]** `existsByCampsiteAndReservationDate` 사용 - 기간 예약과 불일치

#### 기간 검색 (`/api/sites/search`)
- [ ] 시작일과 종료일 필수
- [ ] 종료일이 시작일보다 이전이면 에러
- [ ] 과거 날짜 검색 시 에러
- [ ] **[Critical 버그]** 시작일/종료일만 검사, 중간 날짜 미검사
- [ ] size 파라미터로 대형/소형 필터링 동작

#### API 일관성 검증
```
시나리오: A1 사이트에 1/10~1/12 예약 존재

API별 1/11 가용성 확인:
- [ ] GET /api/sites/A1/availability?date=1/11 → available: false
- [ ] GET /api/sites/available?date=1/11 → A1 미포함
- [ ] GET /api/sites/search?startDate=1/11&endDate=1/11 → A1 미포함
- [ ] POST /api/reservations (1/11~1/11, A1) → 실패

모든 API가 동일한 결과를 반환해야 함
```

#### 취소된 예약 처리
- [ ] CANCELLED 상태 예약은 가용성 계산에서 제외
- [ ] CANCELLED_SAME_DAY 상태 예약도 가용성 계산에서 제외
- [ ] **[버그]** 현재 취소 상태 필터링 없음

#### 동시성 시나리오
```
시나리오: 가용성 확인 후 예약까지의 시간차

T0: 고객A가 1/15 A1 가용성 확인 → available: true
T1: 고객B가 1/15 A1 예약 완료
T2: 고객A가 1/15 A1 예약 시도 → 실패해야 함

- [ ] 가용성 확인과 실제 예약은 별개 트랜잭션
- [ ] 예약 시점에 다시 중복 체크 필수
```

#### 필터링 옵션 검증
- [ ] size=대형 → A로 시작하는 사이트만 반환
- [ ] size=소형 → B로 시작하는 사이트만 반환
- [ ] size 미지정 → 전체 사이트 반환
