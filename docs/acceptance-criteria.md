# 인수 조건

## T-1 30일 넘게 남은 날짜인데 예약이 됨

### 1. 예약 시작일은 오늘로부터 30일 이내여야 한다

```
규칙   예약 시작일은 오늘로부터 30일 이내여야 한다
이유   고객센터 신고("오늘로부터 30일 넘게 남은 날짜인데 예약이 됩니다")를 막기 위한 규칙

Given  시드가 쓰지 않는 사이트
When   시작일이 오늘 + 29일    Then  201 Created, 확인 코드 발급
When   시작일이 오늘 + 30일    Then  201 Created, 확인 코드 발급
When   시작일이 오늘 + 31일    Then  409 "예약 시작일은 오늘로부터 30일 이내여야 합니다."
```

- **현재 상태**: 정상 동작함(`ReservationService.java:93-94`). 실측: `+30일` → `201`, `+31일` → `409` "예약 시작일은 오늘로부터 30일 이내여야 합니다." (30일째는 허용)

### 2. 과거 날짜로 예약할 수 없고, 종료일이 시작일보다 이전일 수 없다

```
규칙   과거 날짜로 예약할 수 없고, 종료일이 시작일보다 이전일 수 없다
이유   T-1을 고치면서 이미 되던 검증이 깨지지 않았는지 판정 단계에서 다시 확인하기 위한 회귀 확인용 조건

Given  시드가 쓰지 않는 사이트
When   시작일이 오늘 이전(과거 날짜)          Then  409 "과거 날짜로 예약할 수 없습니다."
When   종료일이 시작일보다 이전(날짜 역전)    Then  409 "종료일이 시작일보다 이전일 수 없습니다."
```

- **현재 상태**: 정상 동작함(회귀 확인용).

### 3. 예약 완료 시 6자리 영숫자 확인 코드가 생성된다

```
규칙   모든 예약은 영문 대문자+숫자 6자리 확인 코드를 가진다
이유   확인 코드는 예약 취소(DELETE)·수정(PUT)에 필요한 값이므로, T-1 수정 후에도 형식이 유지되는지 판정 단계에서 확인하기 위한 회귀 확인용 조건

Given  시드가 쓰지 않는 사이트, 유효한 예약 요청
When   예약 생성    Then  201 Created, confirmationCode가 영문 대문자+숫자 6자리
```

- **현재 상태**: 정상 동작함(회귀 확인용).

## T-2 전화번호 형식 제한 / 미입력 시 예약 완료

### 1. 전화번호는 필수다. 없으면 예약할 수 없다

```
규칙   예약에는 전화번호가 있어야 한다 (null이거나 공백일 수 없다)
이유   고객센터 신고("전화번호를 안 넣었는데 예약이 완료됐습니다")를 막기 위한 규칙

Given  시드가 쓰지 않는 사이트
When   전화번호 필드를 생략           Then  409 "전화번호를 입력해주세요."
When   전화번호가 공백 문자열         Then  409 "전화번호를 입력해주세요."
When   전화번호에 10~11자리 숫자      Then  201 Created, 확인 코드 발급
```

- **현재 상태**: 정상 동작함(`ReservationService.java:120-121`). 실측: 전화번호 생략 → `409` "전화번호를 입력해주세요."

### 2. 전화번호 형식 검증(하이픈 제거 후 10~11자리 숫자)은 유지한다

```
규칙   예약의 전화번호는 하이픈을 제외하면 10~11자리 숫자여야 한다
이유   T-2를 고치면서(전화번호를 필수로 바꾸면서) 기존 형식 검증 로직이 깨지지 않았는지 판정 단계에서 확인하기 위한 회귀 확인용 조건

Given  시드가 쓰지 않는 사이트
When   하이픈 제거 후 자릿수가 10~11자리가 아님    Then  409 "전화번호 형식이 올바르지 않습니다."
When   하이픈 제거 후 10자리 또는 11자리 숫자       Then  201 Created

질문   자릿수 기준(10~11자리)의 근거는 무엇인가, 국제번호 등 다른 형식은 어떻게 처리하는가 → tickets.md T-7로 별도 관리
```

- **현재 상태**: 정상 동작함(회귀 확인용).

## T-3 취소한 예약의 자리에 다시 예약되지 않음

### 1. 취소된 예약은 같은 사이트·같은 기간의 새 예약을 막지 않는다

```
규칙   같은 사이트·같은 기간에는 취소되지 않은 예약이 하나만 존재할 수 있다 (취소된 예약은 그 자리를 다시 비운다)
이유   고객센터 신고("예약을 취소했는데 같은 날짜에 다시 예약하려니 이미 예약이 있다고 나옵니다")를 막기 위한 규칙

Given  같은 사이트·같은 기간에 CONFIRMED 예약을 취소한 상태
When   같은 사이트·같은 기간으로 재예약    Then  201 Created, 확인 코드 발급
When   같은 사이트·같은 기간에 CONFIRMED 예약이 남아있는 상태에서 겹치는 새 예약    Then  409 "해당 기간에 이미 예약이 존재합니다."
```

- **현재 상태**: 정상 동작함(`ReservationService.java:142-143`, CONFIRMED만 중복 체크). 실측: 예약 생성 → 취소 → 같은 사이트·기간 재예약 → `201 Created`

## T-4 예약자 이름 길이 제한

### 1. 예약자 이름은 2자 이상 20자 이하여야 한다

```
규칙   예약자 이름은 2자 이상 20자 이하여야 한다
이유   지나치게 짧은 이름(오타·의미 없는 입력)이나 지나치게 긴 이름(운영 화면·통계·문자 발송 등에서 표시가 깨지는 것)을 막기 위한 규칙

Given  시드가 쓰지 않는 사이트, 오늘=2026-08-18
When   이름 1자("A")             Then  409 "예약자 이름은 최소 2자 이상이어야 합니다."
When   이름 2자("AB")            Then  201 Created
When   이름 20자                 Then  201 Created
When   이름 21자                 Then  409 "예약자 이름은 최대 20자까지 가능합니다."
```

- **현재 상태**: 정상 동작함(`ReservationService.java:112-117`). 이 규칙은 생성·수정 모든 경로에 동일하게 적용돼야 한다.

### 2. 예약 수정 경로에도 이름 길이 제한이 적용돼야 한다

```
규칙   위 1번 규칙(이름 2~20자)은 예약 수정 시에도 동일하게 적용된다
이유   같은 도메인 규칙이 생성 경로에만 걸리고 수정 경로로 우회되면 규칙 자체가 무의미해지므로

Given  CONFIRMED 상태의 기존 예약
When   수정(PUT) 시 이름 1자("A")        Then  400 "예약자 이름은 최소 2자 이상이어야 합니다." (PUT은 검증 실패 시 400 반환, POST의 409와 다름)
When   수정(PUT) 시 이름 33자            Then  400 "예약자 이름은 최대 20자까지 가능합니다."
```

- **현재 상태(버그)**: `updateReservation`(`ReservationService.java:395-400`)은 길이 검증이 없어 이 규칙을 위반한다. 실측: PUT으로 이름 1자·33자 모두 `200`으로 그대로 저장됨.
