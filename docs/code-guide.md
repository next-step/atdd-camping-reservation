# 메서드 이름은 무엇을 검증하는지 드러낸다

`check`, `validate` 만으로는 무엇을 거절하는지 알 수 없다. 거절하는 대상을 이름에 넣는다.

이유 — 인수 조건은 규칙 하나가 거절 문구 하나와 짝이다.
이름이 그 짝을 가리키지 않으면 어느 규칙이 어디에 구현됐는지 코드를 다 읽어야 안다.

# 메서드를 새로 만들면 자리도 함께 판정한다

파일 끝에 붙이지 않는다. 호출부의 순서와 기존 배치를 근거로 들어 자리를 고르고, 그 근거를 밝힌다.

이유 — 끝에 붙이기를 반복하면 검증 순서와 코드 순서가 어긋난다.
다음 티켓에서 검증을 하나 더 넣을 때 어디에 넣어야 할지 판단할 근거가 사라진다.
