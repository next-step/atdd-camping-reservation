# 작업 계획

티켓 하나를 처리하는 순서다. 지켜야 하는 것은 `principles.md`에 있다.

각 단계는 `docs/skills/`의 스킬이 실행한다(2026-08-20 스킬화). 스킬과 이 계획이
어긋나면 둘을 함께 고친다. 스킬 사이 — 각 스킬의 "넘어가기 전에 사람이 확인할 것" —
는 사람이 확인하고 다음 스킬을 부르는 자리다. 한 번에 이어 돌리지 않는다.

## 1. 인수 조건 — 실행 스킬: `skills/ticket-ac.md` (`/ticket-ac`)

- 입력: 티켓, 이 티켓에서 다룰 요구사항
- 하는 일: 코드에서 지금 동작을 파악하고, 요구사항과 어긋나는 자리를 판정한다
- 남기는 것: `acceptance-criteria.md`에 규칙과 예시와 이유. 못 정한 것은 질문으로, 남은 일은 `tickets.md`에
- 넘어가기 전에: 예시가 직접 호출해 받은 응답인지 확인한다
- AI에게 주는 지시:
  - "요구사항의 '없음/필수'는 들어오는 형태를 전부 실측해라 — 필드 누락, 빈 문자열, 공백만은 서로 다른 요청이다." (T-2)
  - "실측용 사이트는 시드(`data.sql`)와 기존 테스트가 쓰는 것을 피해서 골라라." (T-1·T-2 두 번 필요 — 스킬 후보)

## 2. 인수 테스트 — 실행 스킬: `skills/ticket-test.md` (`/ticket-test`)

- 입력: `acceptance-criteria.md`, `test-guide.md`
- 하는 일: 테스트 초안을 받아 규칙을 검증하는지 판정하고 실행한다
- 남기는 것: 테스트 코드. 초안에 준 제약은 `test-guide.md`에 규칙 한 줄로
- 넘어가기 전에: 인수 테스트가 지금 실패하는지 확인한다. 실패하지 않으면 지금 동작을 겨눈 초안이다
- AI에게 주는 지시: (아래 다섯 줄은 T-1·T-2에서 그대로 재사용 — 스킬로 굳힐 자리)
  - "`acceptance-criteria.md`의 규칙 하나에 테스트 하나를 붙여라. 테스트 이름에 규칙 번호를 넣어라."
  - "경계는 양쪽을 단언해라. 통과하는 값과 거부되는 값을 각각 하나씩."
  - "이번 티켓에서 새로 넣는 규칙의 테스트는 **지금 실패해야 한다**. 기존 동작 규칙은 지금 통과해야 한다."
  - "확정되지 않은 것은 단언하지 마라. 문구가 미정이면 상태 코드만 본다."
  - "제약은 `test-guide.md`를 먼저 읽고 그대로 따라라."

## 3. 구현 — 실행 스킬: `skills/ticket-impl.md` (`/ticket-impl`)

- 입력: 실패하는 인수 테스트
- 하는 일: 그 테스트를 통과시키는 최소 변경
- 남기는 것: 코드
- 넘어가기 전에: 실패하던 인수 테스트가 통과하는지 확인한다
- AI에게 주는 지시:
  - "이웃한 검증 블록과 같은 모양으로 고쳐라. 새 스타일을 들이지 마라." (T-2: 이름 검증의 guard-throw 모양을 따랐다)
  - "생성 경로만 고쳐라. 다른 경로(수정·조회)의 같은 구멍은 티켓에 실측만 보태라." (T-1의 F-5·F-8, T-2의 F-5 추가 실측 — 두 번 필요, 스킬 후보)

## 4. 판정 — 실행 스킬: `skills/ticket-verdict.md` (`/ticket-verdict`)

- 입력: 바뀐 코드, 쌓인 테스트 전부
- 하는 일: 이 티켓이 끝났는지 판정한다. 바뀐 코드를 읽고, 쌓인 테스트를 전부 돌려 회귀를 확인한다
- 남기는 것: 커밋. 처리하며 발견한 것이 있으면 `tickets.md`에
- 넘어가기 전에: 요구사항대로 됐고 원래 되던 것이 안 깨졌는지 확인한다
- AI에게 주는 지시:
  - "늘 통과하는 테스트는 값을 일부러 틀리게 바꿔 실패하는지 보고 되돌려라(고장내기)." (T-1·T-2 두 번 필요 — 스킬 후보)
  - "서버를 재기동해 인수 조건의 예시를 재실측하고, '이 티켓 이후' 칸을 실제 응답으로 채워라. 구 프로세스가 포트를 잡고 있으면 응답 데이터로 알아챈다." (T-2: 구 서버가 옛 코드로 응답하고 있었다)

## 이 저장소의 실행 방법

- 서버 기동: `./gradlew bootRun`, 8080 포트. 8080이 쓰이면 `SERVER_PORT=8081 ./gradlew bootRun`
- 호출할 수 있는 것은 `/api` 아래에 있다
- 테스트 실행: `./gradlew test`. 결과 줄이 안 보이면 캐시다. `./gradlew test --rerun-tasks`로 다시 돌린다
- 데이터를 다루기 전에 `src/main/resources/data.sql`을 읽는다

테스트를 어떻게 짤지는 이 파일에 적지 않는다. 무엇을 단언하고 어떻게 격리할지는
작업하며 정해 `test-guide.md`에 쌓는다.

## AI에게 주는 지시 칸

단계마다 마지막 줄이 비어 있다. 그 단계에서 AI에게 실제로 준 지시 중 다시 쓸 만한
것을 적는 자리다. 프롬프트 전문을 옮기지 않고, 다음에도 그대로 쓸 문장만 남긴다.

두 번째 티켓에서 같은 지시를 또 하게 되면 그것이 굳힐 자리다. 네 칸에 쌓인 것이
스킬을 만들 때의 재료가 된다.
