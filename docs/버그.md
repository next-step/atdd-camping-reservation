## 버그 발견 후 
- 버그 발견 -> 실패하는 테스트 작성 -> 버그 수정 -> 테스트 통과

## 버그 리스트 
### 동시_예약_요청시_하나만_성공
- 테스트 : ReservationAcceptanceTest.동시_예약_요청시_하나만_성공
- 발견 방법 : 디버깅 툴, 테스트 실행 -> false 값 리턴 확인
- exist..로 확인하고 저장하는 사이에 간격이 있음 
#### 여러 해결 방법
- exists.. 쿼리에 락을 걸어도 조회 결과가 없으면 락 대상이 없어서 동시성 제어 불가
- (1) 부모 테이블 비관적 락
  - Campsite에 PESSIMISTIC_WRITE
- (2) Unique Constraint
  - DB 제약 조건으로 중복 방지
    - 날짜 범위 겹침을 제약조건으로 표현 불가
- (3) 낙관적 락 + 재시도 
  - @Version + 충돌 시 OptimisticLockException 재시도 
    - Insert 시나리오에서는 Version 비교 대상 없음
- (4) 분산락 (Redis) 
  -  인프라 추가 필요, 오버엔지니어링
##### 부모 테이블 비관적 락 선택 이유 
- 동시 요청이 많지 않음 (초당 수십 건 이하)
  - 일일 2000건 (성수기 ) : 시간당 ~83건, 분당 ~1.4건, 초당 0.02건 
- 재시도 로직, 예외 처리 등 추가 코드 불필요
- DB 레벨에서 락 → 100% 동시성 문제 해결
