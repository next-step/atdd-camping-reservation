# Top 3 핵심 시나리오 5W1H 명세화

리스크 분석 결과에 따라 가장 중요한 시나리오 3가지를 선정하고, 5W1H 원칙으로 구체화하여 명확한 인수 조건을 정의합니다.

---

## 1. 중복 예약 방지 (예약 생성)

### 5W1H 명세

| 항목 | 내용 |
|------|------|
| **Who (누가)** | 김철수 (새로운 예약자) |
| **What (무엇을)** | 이미 홍길동이 예약한 A-1 캠핑 사이트를 |
| **When (언제)** | 2024년 8월 15일 (이미 예약된 날짜에) |
| **Where (어디서)** | 캠핑 예약 시스템에서 |
| **Why (왜)** | 이중 예약을 방지하여 예약 시스템의 신뢰성과 데이터 무결성을 보장하기 위해 |
| **How (어떻게)** | 예약 요청 시 시스템이 기존 예약을 감지하고, "해당 기간에 이미 예약이 존재합니다"라는 오류 메시지와 함께 예약 요청을 거부한다 |

### 인수 조건

```gherkin
Scenario: 중복 예약 방지
  Given 2024년 8월 15일부터 8월 17일까지 A-1 사이트가 홍길동에게 예약되어 있다
  When 김철수가 같은 기간에 A-1 사이트를 예약 시도한다
  Then 예약이 거부된다
  And "해당 기간에 이미 예약이 존재합니다" 메시지를 받는다
```

### 검증 포인트
- [ ] 동일 사이트, 동일 날짜 예약 시 거부된다
- [ ] 기간이 일부만 겹쳐도 거부된다 (8월 16일~18일 시도 시)
- [ ] 동시 예약 요청(Race Condition) 시에도 하나만 성공한다
- [ ] 적절한 오류 메시지가 반환된다

## 2. 취소된 예약 수정 방지 (예약 수정)

### 5W1H 명세

| 항목 | 내용 |
|------|------|
| **Who (누가)** | 박영희 (예약 취소한 고객) |
| **What (무엇을)** | 이미 취소된 예약 DEF456을 |
| **When (언제)** | 취소 후 다음 날 (예약 상태가 CANCELLED인 상황에서) |
| **Where (어디서)** | 캠핑 예약 시스템에서 |
| **Why (왜)** | 취소된 예약의 무결성을 보장하고 잘못된 상태 변경을 방지하기 위해 |
| **How (어떻게)** | 수정 요청 시 시스템이 예약 상태를 확인하고, "취소된 예약은 수정할 수 없습니다"라는 오류 메시지와 함께 수정 요청을 거부한다 |

### 인수 조건

```gherkin
Scenario: 취소된 예약 수정 방지
  Given 확인 코드 "DEF456"인 예약이 취소 상태(CANCELLED)이다
  When 박영희가 확인 코드 "DEF456"으로 날짜 변경을 요청한다
  Then 수정이 거부된다
  And "취소된 예약은 수정할 수 없습니다" 메시지를 받는다
```

### 검증 포인트
- [ ] CANCELLED 상태의 예약은 수정할 수 없다
- [ ] CANCELLED_SAME_DAY 상태의 예약도 수정할 수 없다
- [ ] CONFIRMED 상태의 예약만 수정할 수 있다
- [ ] 적절한 오류 메시지가 반환된다

## 3. 취소된 예약 캘린더 제외 (월별 캘린더)

### 5W1H 명세

| 항목 | 내용 |
|------|------|
| **Who (누가)** | 관리자 (캠핑장 운영자) |
| **What (무엇을)** | A-1 사이트의 8월 캘린더에서 취소된 예약을 |
| **When (언제)** | 고객이 예약을 취소한 이후 |
| **Where (어디서)** | 캠핑 예약 관리 시스템의 캘린더 조회 화면에서 |
| **Why (왜)** | 실제 이용 가능한 날짜를 정확히 표시하여 신규 예약을 받을 수 있도록 하기 위해 |
| **How (어떻게)** | 캘린더 조회 시 시스템이 취소된 예약을 제외하고, 해당 날짜를 "이용 가능" 상태로 표시한다 |

### 인수 조건

```gherkin
Scenario: 취소된 예약은 캘린더에서 제외
  Given A-1 사이트에 2024년 8월 20일부터 8월 22일까지 예약이 있었다
  And 해당 예약이 취소되었다
  When 관리자가 A-1 사이트의 2024년 8월 캘린더를 조회한다
  Then 8월 20일, 21일, 22일은 "이용 가능" 상태로 표시된다
  And 새로운 예약을 받을 수 있다
```

### 검증 포인트
- [ ] 취소된 예약(CANCELLED)은 캘린더에 표시되지 않는다
- [ ] 당일 취소(CANCELLED_SAME_DAY)도 캘린더에서 제외된다
- [ ] 취소된 날짜에 새로운 예약이 가능하다
- [ ] 확정된 예약(CONFIRMED)만 캘린더에 표시된다
