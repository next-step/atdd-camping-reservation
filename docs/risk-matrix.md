# 5. 리스크 기반 요약

*   **전체 기능 중 리스크가 집중된 영역 요약**:
    *   **예약 핵심 기능군**: 예약 생성(POST), 취소(DELETE), 수정(PUT) 기능은 비즈니스 임팩트와 버그 가능성 모두 높아 가장 위험도가 높은 영역으로 파악됩니다. 이는 시스템의 핵심 동작이며, 동시성 문제, 복잡한 비즈니스 규칙, 데이터 정합성 이슈가 복합적으로 존재합니다.
    *   **개인 정보 접근 관련 기능**: `GET /api/reservations/my`와 같이 개인 예약 정보를 조회하는 기능은 인증 부재로 인해 심각한 보안 리스크를 내포하고 있습니다.
    *   **대량 데이터 처리 기능**: 예약 목록 조회(`GET /api/reservations`) 및 캘린더 조회(`GET /api/reservations/calendar`)는 `findAll()` 후 필터링하는 방식으로 인해 데이터 증가 시 성능 저하 위험이 높습니다.

*   **인수 초기에 특히 주의해야 할 공통 패턴 2~3가지**:
    1.  **동시성 제어 및 트랜잭션**: 예약 생성 및 가용성 확인 로직에 명시적인 `Thread.sleep`과 함께 `exists` 쿼리만 사용하는 패턴은 오버부킹과 같은 치명적인 동시성 문제를 유발할 수 있습니다. 이는 시스템 전반의 신뢰도를 저하시킬 수 있습니다.
    2.  **인증/인가 부재로 인한 보안 취약점**: 이름/전화번호 기반의 단순 식별 방식은 고객의 개인 정보와 예약 내역을 무단으로 조회하고 조작할 수 있는 경로를 제공하여 심각한 보안 위험을 초래합니다.
    3.  **애플리케이션 레벨의 비효율적인 데이터 처리**: `findAll()` 호출 후 대량 데이터를 메모리에 로드하여 처리하는 방식이 여러 조회 기능에서 발견됩니다. 이는 시스템 자원 소모를 증가시키고, 데이터 규모가 커질수록 서비스의 안정성과 응답 속도에 부정적인 영향을 미칩니다.
