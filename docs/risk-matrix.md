# 리스크 매트릭스

## 평가 기준
- **척도**: 높음(3점), 보통(2점), 낮음(1점)
- **계산식**: 리스크 점수 = 비즈니스 임팩트 + 변경 빈도 + 버그 가능성

## 평가 결과

| 기능 | 비즈니스 임팩트 | 변경 빈도 | 버그 가능성 | 총점 | 순위 |
|-----|----------------|----------|------------|------|------|
| 예약 생성 | 높음(3) | 높음(3) | 높음(3) | 9 | 1 |
| 예약 취소 | 높음(3) | 보통(2) | 보통(2) | 7 | 2 |
| 예약 수정 | 보통(2) | 보통(2) | 높음(3) | 7 | 3 |

## Top 3 선정 근거

### 1. 예약 생성 (9점)
**비즈니스 임팩트**: 매출 직결, 예약 실패 시 고객 이탈

**발견된 문제점**:
- 동시성: `Thread.sleep(100)` + 잠금 없음 → Race Condition으로 중복 예약 발생 가능
- 복잡도: 213줄 메서드, 검증/가격계산/포인트/알림이 한 곳에
- 중복: 가격 계산 로직이 3곳에서 반복
- 검증: 날짜/이름/전화번호 검증이 여러 곳에 분산

### 2. 예약 취소 (7점)
**비즈니스 임팩트**: 환불/재고 관리 영향, 잘못된 취소는 고객 불만 야기

**발견된 문제점**:
- 당일/사전 취소 구분 로직 (startDate == today)
- 상태값이 문자열로 관리 (ENUM 미사용)
- 확인코드 검증 로직 중복

### 3. 예약 수정 (7점)
**비즈니스 임팩트**: 고객 편의 기능

**발견된 문제점**:
- 날짜 변경 시 중복 예약 재검증 필요
- 부분 수정 시 null 체크 복잡
- 검증 로직이 createReservation과 중복
