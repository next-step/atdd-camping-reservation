## Top 3 선정 근거

### 1. 예약 생성 (9점)

**선정 이유**: 매출과 직결되는 핵심 기능이며, 동시성 이슈, 취소 예약 필터링 누락 등 복잡도가 높아 리스크가 가장 크다고 판단.

- 비즈니스 임팩트(3): 예약 불가 시 매출 직접 손실
- 변경 빈도(3): 검증 규칙, 가격 정책 변경 가능성 높음
- 버그 가능성(3): 동시성 버그, 중복 예약, 검증 누락 등 다수 발견

---

### 2. 연박 예약 검증 (8점)

**선정 이유**: 3박 4일 등 연박 예약 시 중간 날짜 가용성을 확인하지 않아, 실제로 사용 불가능한 기간에 예약이 생성될 수 있음.

- 비즈니스 임팩트(3): 고객이 현장에서 사이트 사용 불가 발생 가능
- 변경 빈도(2): 연박 할인 정책 등 추가 가능
- 버그 가능성(3): 시작일/종료일만 확인하고 중간 날짜 미확인

**문제 코드**:
```java
// SiteService.searchAvailableSites()
boolean startAvailable = !repo.existsByCampsiteAndReservationDate(site, startDate);
boolean endAvailable = !repo.existsByCampsiteAndReservationDate(site, endDate);
// 중간 날짜는 확인하지 않음!
```

---

### 3. 동시성 제어 (7점) / 예약 수정 (8점)

**동시성 제어 선정 이유**: 두 고객이 동시에 같은 사이트를 예약할 때 중복 예약이 발생할 수 있음. Thread.sleep(100)으로 인해 Race Condition이 발생.

- 비즈니스 임팩트(3): 중복 예약 시 고객 분쟁, 신뢰도 하락
- 변경 빈도(1): 한 번 수정하면 안정적
- 버그 가능성(3): Thread.sleep으로 의도적 경쟁 조건 발생

**예약 수정 선정 이유**: 예약 수정 시 변경된 날짜/사이트에 대한 중복 체크가 누락되어, 수정을 통해 중복 예약 생성 가능.

- 비즈니스 임팩트(3): 중복 예약으로 인한 운영 혼란
- 변경 빈도(2): 수정 가능 항목 확장 가능
- 버그 가능성(3): 중복 체크 로직 누락
