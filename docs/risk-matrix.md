## 3. Top 3 선정 근거

### 3.1 예약 생성 (9점) - 1순위

**비즈니스 임팩트: 높음(3)**
- 캠핑장 매출과 직결되는 핵심 기능
- 예약 실패 시 고객 이탈 및 매출 손실 발생

**변경 빈도: 높음(3)**
- 가격 정책(주말 할증, 성수기 할증) 변경 가능성 높음
- 검증 규칙(예약 기간, 인원 제한) 수시 변경 예상
- 포인트 적립 정책 변경 가능

**버그 가능성: 높음(3)**
- **동시성 문제**: `Thread.sleep(100)` 존재로 Race Condition 발생 가능 (`ReservationService:137-141`)
- **깊은 중첩**: 4~5단계 if-else 체인으로 가독성 저하 및 버그 발생 가능성
- **12개 이상의 검증 케이스**: 경계값, 예외 케이스 누락 가능성
- **가격 계산 로직 중복**: 두 곳에 동일 로직이 존재하여 불일치 위험

```
관련 코드 스멜:
- ReservationService:82-100 (깊은 중첩)
- ReservationService:137-141 (동시성 문제)
- ReservationService:146-180, 513-541 (가격 계산 중복)
```

---

### 3.2 예약 수정 (8점) - 2순위

**비즈니스 임팩트: 높음(3)**
- 고객의 예약 변경 요청 처리는 서비스 품질의 핵심
- 잘못된 수정으로 중복 예약 발생 시 운영 혼란

**변경 빈도: 보통(2)**
- 예약 생성보다는 적지만 수정 정책 변경 가능
- 수정 가능 기간, 수정 횟수 제한 등 규칙 추가 가능

**버그 가능성: 높음(3)**
- **동시성 문제**: 예약 생성과 동일한 패턴으로 Race Condition 존재 (`ReservationService:210-214`)
- **7개 검증 케이스**: 기존 예약 정보와 새 정보 간 충돌 검사 필요
- **기존 예약과 충돌 검사**: 자기 자신을 제외한 충돌 검사 로직의 복잡성

```
관련 코드 스멜:
- ReservationService:210-214 (동시성 문제)
- 날짜 검증 로직 중복 (ReservationService, SiteService, ValidationUtils)
```

---

### 3.3 예약 취소 (7점) - 3순위

**비즈니스 임팩트: 높음(3)**
- 환불/정산 로직과 연결되는 중요 기능
- 취소 처리 오류 시 정산 불일치 발생

**변경 빈도: 보통(2)**
- 취소 수수료 정책 변경 가능
- 당일 취소, 노쇼 페널티 등 규칙 추가 가능

**버그 가능성: 보통(2)**
- **상태 변경 규칙**: 당일 취소(`CANCELLED_SAME_DAY`)와 사전 취소(`CANCELLED`) 분기
- **확인 코드 검증**: 보안 관련 로직으로 정확한 검증 필요
- 취소 후 사이트 가용성 즉시 반영 여부

```
관련 코드 스멜:
- ReservationService:311 (당일 취소 구분 로직)
- 일관성 없는 예외 처리 (RuntimeException만 사용)
```
