# ticket-impl — 3. 구현

실패하는 인수 테스트를 통과시키는 최소 변경을 한다. `plan.md` 3단계를 실행한다.

## 읽는 것

- 실패하는 인수 테스트와 `docs/acceptance-criteria.md`의 해당 규칙
- 고칠 지점 주변 코드 — 특히 **이웃 검증 블록의 모양**

## 하는 일

1. 인수 조건 단계에서 특정한 원인 지점(`파일:줄`)만 고친다.
   이웃 블록과 같은 모양으로 — 새 스타일·새 추상화를 들이지 않는다.
2. 티켓의 범위를 지킨다. 범위 밖의 같은 구멍(수정·조회 경로 등)은
   고치지 말고 해당 F-n에 실측만 보탠다.
3. 문구가 필요한데 미확정(Q-n)이면 코드베이스에 이미 있는 문구를 재사용하고,
   그 사실을 Q-n에 적는다.
4. 전체 테스트를 돌려 실패하던 것이 통과하는지 본다: `./gradlew test --rerun-tasks`.

## 남기는 것

- 최소 변경 코드. (커밋은 `/ticket-verdict`에서 판정 결과와 함께 만든다.)

## 넘어가기 전에 사람이 확인할 것

- diff가 최소인가 — 티켓과 무관한 정리·리팩터링이 섞이지 않았는가
- 범위 밖(다른 경로·다른 규칙)을 건드리지 않았는가
