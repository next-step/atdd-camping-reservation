# ticket-verdict — 4. 판정

이 티켓이 끝났는지 판정하고 커밋한다. `plan.md` 4단계를 실행한다.

## 읽는 것

- 바뀐 코드 전부 (`git diff`)
- 쌓인 테스트 전부, `docs/acceptance-criteria.md`의 이번 티켓 예시

## 하는 일

1. 전체 테스트: `./gradlew test --rerun-tasks`. 전부 통과해야 한다.
2. **고장내기** — 늘 통과하는 테스트는 값을 일부러 틀리게 바꿔 실패하는지 보고 되돌린다.
   안 깨지면 그 단언은 빈 껍데기다. (구현 전에 늘 통과하던 테스트가 대상이다.)
3. **재실측** — 서버를 새 코드로 재기동한다. 옛 JVM이 8080을 잡고 있을 수 있다:
   예약 개수(시드 5건)나 응답 데이터로 새 인스턴스인지 확인하고,
   아니면 `netstat -ano | grep 8080`으로 PID를 찾아 내린 뒤 다시 띄운다.
4. `acceptance-criteria.md`의 "이 티켓 이후 →" 칸을 실제 응답으로 채운다.
5. **고객 신고 시나리오를 서버에서 그대로 재현**해 명령과 응답 원본을
   `tickets.md`의 해당 티켓 아래에 붙인다.
6. 회귀 스모크: GET 조회 경로 전부 200, 이전 티켓들의 경계가 유지되는지 직접 호출.
7. 신고 증상이 **다른 경로로 아직 재현되면** 티켓을 닫지 말고 그 실측을
   `acceptance-criteria.md`에 적는다. (T-1의 Q-1 전례 — "구현 완료, 종결 보류")
8. 커밋 — `T-n 구현: <한 줄>`. 본문에 테스트 수, 고장내기 결과, 회귀 스모크,
   **의도적으로 안 고친 것**(범위 밖 구멍과 그 F-n 번호).
9. `plan.md` 지시 칸에 이번에 다시 쓴/새로 쓴 지시를 적고,
   `retrospective.md`에 확인 결과 한 줄을 남긴다.

## 남기는 것

- 커밋 (구현 + 문서), `tickets.md`의 재현 원본, `plan.md` 지시 칸, `retrospective.md` 한 줄

## 넘어가기 전에 사람이 확인할 것

- 커밋이 티켓당 3개 단위(인수 조건 / 실패 테스트 / 구현+판정)로 남았는가
- 티켓을 닫을 수 있는가 — Q-n이 남았으면 "구현 완료, 종결 보류"로 두었는가
