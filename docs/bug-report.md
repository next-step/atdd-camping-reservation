# 🐛 버그 리포트 및 수정 우선순위

현재 테스트 코드(`@Disabled`)를 통해 확인된 비즈니스 로직 버그 목록입니다.
비즈니스 중요도와 데이터 무결성에 미치는 영향을 고려하여 우선순위를 선정했습니다.

## 🚨 P0: 치명적 (Critical)
**데이터 무결성을 해치고 서비스의 핵심 신뢰도를 떨어뜨리는 버그**

### 1. 동시성 이슈: 중복 예약 발생 가능
- **위치**: `ReservationAcceptanceTest.java` > `예외_동시에_동일_사이트_기간으로_예약_요청이_여러_건_들어와도_하나만_성공해야_한다`
- **현상**: 동일한 사이트와 날짜에 대해 동시에 여러 예약 요청이 들어올 경우, 격리 수준이나 락(Lock) 제어가 없어 중복 예약이 발생할 수 있음.
- **영향**: 오버부킹 발생 시 고객 클레임 및 금전적 손실 직결.

---

## 🚧 P1: 높음 (High)
**핵심 비즈니스 규칙이 누락되어 데이터 꼬임이 발생할 수 있는 버그**

### 2. 예약 수정 시 기간 중복 검증 누락
- **위치**: `UpdateReservationAcceptanceTest.java` > `변경된_예약이_다른_예약과_기간이_겹치면_수정이_거부된다`
- **현상**: 기존 예약을 수정할 때, 변경하려는 기간에 이미 다른 예약이 존재하는지 확인하는 로직이 없음.
- **영향**: 예약 수정 기능을 악용하거나 실수로 인해 겹치기 예약(Double Booking) 발생 가능.

---

## ⚠️ P2: 중간 (Medium)
**비즈니스 정책 위반이지만 시스템 오류로 이어지지는 않는 버그**

### 3. 예약 수정 시 최대 기간(30일) 제한 누락
- **위치**: `UpdateReservationAcceptanceTest.java` > `예외_변경된_예약_기간이_30일을_초과하면_수정이_거부된다`
- **현상**: 예약 생성 시에는 30일 제한이 적용되나, 수정 시에는 해당 검증 로직이 빠져있음.
- **영향**: 장기 투숙 정책 우회 가능.

---

## ℹ️ P3: 낮음 (Low)
**사용자 경험(UX)이나 입력값 검증과 관련된 버그**

### 4. 사이트 검색 시 날짜 유효성 검증 미흡
- **위치**: `SiteSearchAcceptanceTest.java`
  - `예외_과거_날짜로_기간_검색을_시도하면_실패한다`
  - `예외_종료일이_시작일보다_이전이면_기간_검색이_실패한다`
- **현상**: 검색 파라미터로 과거 날짜나 잘못된 기간(종료일 < 시작일)을 입력했을 때, 적절한 에러 메시지(400 Bad Request) 대신 500 에러가 나거나 잘못된 결과가 반환됨.
- **영향**: API 사용자에게 불친절한 응답 제공, 프론트엔드 예외 처리 복잡도 증가.
