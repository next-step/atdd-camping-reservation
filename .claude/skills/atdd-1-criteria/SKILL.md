# 1단계 — 인수 조건

이 티켓의 통과 기준을 세운다. **코드는 만지지 않는다.**

## 읽는 것

| 파일 | 왜                                         |
|---|--------------------------------------------|
| `docs/principles.md` | 지켜야 하는 것.                            |
| `docs/tickets.md` | 받은 티켓의 요구사항과 API 스펙, 실측 기록 |
| `docs/acceptance-criteria.md` | 앞 티켓이 세운 규칙. 이번 변경이 깨뜨릴 것 |
| `src/main/resources/data.sql` | 시드가 이미 점유한 사이트·날짜 |

## 하는 일

### 1. 실측할 서버를 띄운다

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN          # 이미 떠 있으면 이전 세션의 낡은 코드다
SERVER_PORT=8081 ./gradlew bootRun        # 포트가 물려 있으면 빈 포트로 옮긴다
```

`bootRun` 이 tmpdir 권한으로 죽으면:

```bash
./gradlew bootJar && java -Djava.io.tmpdir=$TMPDIR -jar build/libs/*.jar
```

호출할 수 있는 것은 `/api` 아래에 있다.

**낡은 서버의 응답을 실측으로 쓰면 판정 전체가 거짓이 된다.** 포트 확인은 건너뛰지 않는다.
DB 는 H2 인메모리라 기동마다 초기화된다. 재기동했으면 앞서 받은 id 와 확인 코드는 죽은 값이다.

### 2. 경계를 직접 호출한다

한 규칙마다 **넘는 값 / 경계값 / 안쪽 값** 셋을 부른다.
케이스마다 다른 사이트를 쓴다. `data.sql` 시드가 잡은 사이트도 피한다.

**경계가 몇 개인지 먼저 센다.** 기간·범위를 다루는 규칙은 경계가 둘이다.
한쪽만 부르면 한쪽 끝만 비교하는 구현도 통과한다.

### 3. 나눠서 판정한다

- **신고된 증상** — 기대와 지금 응답이 다른 자리. "지금 응답"과 "기대 응답"을 나눠 적는다
- **회귀 규칙** — 지금도 통과하는데 이번 변경으로 깨질 수 있는 것
- **침묵하는 자리** — 요구사항에 없는데 코드가 강제하거나 허용하는 것. **답을 만들지 않는다.** 티켓으로 등록만 하고 이번 티켓에서 처리하지 않는다

요구사항이 침묵하면 선택지로 묻는다. 선택지마다 경계 시나리오가 어떻게 달라지는지 함께 보인다.

## 남기는 것

- `docs/acceptance-criteria.md` — 이 티켓의 규칙
- `docs/tickets.md` — 받은 티켓의 요구사항·API 스펙, 실측 기록, 그리고 발견한 티켓
- 커밋 `docs: T-N 인수 조건 확정과 발견 티켓 등록` — **바로 커밋하지 않는다.** 커밋할 내용을 보이고 사용자가 확인한 뒤에만 한다

티켓과 인수 조건은 **요구사항과 API 스펙**으로 쓴다. 클래스명·메서드명 같은 코드 세부는 넣지 않는다.

## 쓰는 형식

### `tickets.md`

````
## T-N <제목>

경위: 고객센터 신고 — "<신고 문구 그대로>"
      또는  T-M 의 <무엇>을 실측하다 나왔다

지금 어떤가
- <서술>
  실측: `<요청>` → `<응답>`

요구사항
- <이번에 바꾸는 것>
- <범위 밖인 것>은 따로 본다(T-M).

API 스펙
- `<METHOD> /api/...` — <조건>이면 `<코드>` + `{"message":"..."}`
- 기존 응답(<무엇>)은 그대로 둔다.

인수 조건: `acceptance-criteria.md`의 T-N

실측 기록

1. <인수 조건의 절 제목 그대로> (실측 YYYY-MM-DD, NNNN 포트)
```
# <무엇을 부르는지>
curl ...

<상태 코드>
<응답 본문 그대로>
```

---
````

- 아직 정하지 않은 티켓도 **칸을 비우지 않는다.** 무엇이 안 정해졌는지를 보이게 한다.
- 정하지 않은 것에 답을 만들지 않는다. 물음으로 남긴다
- 티켓 사이는 `---` 와 빈 줄

### `acceptance-criteria.md`

````
## T-N <규칙을 한 줄로>

### 1. <경로> — <무엇>

```
규칙   <무엇을 받고 무엇을 거절하는가>
이유   <왜 그렇게 정했는가. 신고 문구를 인용한다>

Given  <시드가 쓰지 않는 사이트, 준비된 상태>
When   <입력>            Then  <기대 응답>
                         지금  <실제 응답> — 신고된 증상
When   <입력>            Then  <기대 응답>                    (회귀)

질문   <물음> — T-M. 정해지기 전까지 지금 동작인 "<지금>"을 유지한다
```
````

- **한 섹션 = 한 코드펜스.** `규칙` `이유` `Given/When/Then` `질문` 이 전부 그 안에 들어간다
- 티켓 사이는 `---` 와 빈 줄

## 자기 점검

- [ ] 인수 조건의 모든 `지금` 이 **직접 호출해 받은 응답**인가. 코드를 읽고 추론한 것이 하나도 없는가
- [ ] 그 근거인 호출과 응답 전문이 `tickets.md` 의 실측 기록에 남았는가. 번호와 제목이 인수 조건의 절과 맞는가
- [ ] 실측에 쓴 포트의 서버가 지금 코드로 뜬 것이 맞는가
- [ ] 신고된 증상 외에 **회귀 규칙**을 적었는가
- [ ] 침묵하는 자리를 답으로 메우지 않고 티켓으로 넘겼는가
