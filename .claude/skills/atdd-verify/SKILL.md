# 4. 판정

`docs/principles.md`, `docs/plan.md`를 먼저 읽는다.

## 입력

- 바뀐 코드
- 쌓인 테스트 전부

## 하는 일

- 바뀐 코드를 읽는다.
- `./gradlew test`(필요하면 `--rerun-tasks`)로 쌓인 테스트를 전부 돌려 회귀를 확인한다.
- 요구사항대로 됐고 원래 되던 것이 안 깨졌는지 판정한다.

## AI에게 주는 지시

- 테스트 실행 결과(빨강→초록 전환)를 사람에게 보여주고 확인받은 뒤에만 커밋한다.
  AI 혼자 통과했다고 판단해 커밋까지 진행하지 않는다. 커밋 직전에 반드시
  AskUserQuestion으로 "이대로 커밋할까요?"를 묻고, 승인 응답을 받은 뒤에만
  `git commit`을 실행한다.
- 이번 티켓으로 그린이 된 인수 테스트의 `@Nested` Javadoc이 레드였던 시절 문구
  그대로 남아 있지 않은지 확인하고, 남아 있으면 갱신한다(규칙은 `test-guide.md`).

## 남기는 것

- 커밋 (사용자 승인 후에만)
- 처리하며 발견한 것이 있으면 `docs/tickets.md`에 남긴다.

## 넘어가기 전에 (하드 게이트)

전체 테스트의 빨강→초록 전환 결과를 사용자에게 보여주고, AskUserQuestion으로 커밋
승인을 받는다. 승인 전에는 `git add`/`git commit`을 실행하지 않는다.
