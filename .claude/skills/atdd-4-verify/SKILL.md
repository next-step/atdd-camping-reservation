# 4단계 — 판정

이 티켓이 끝났는지 판정한다.

## 읽는 것

| 파일 | 왜 |
|---|---|
| 이번 티켓의 변경 전부 (`git diff`) | 최소 변경이었는지 |
| `docs/acceptance-criteria.md` | 세운 규칙과 회귀 규칙 |
| `docs/tickets.md` | 이번에 처리하지 않기로 한 것 |

## 하는 일

### 1. 쌓인 테스트를 전부 돌린다

```bash
./gradlew test --rerun-tasks
```

이번 티켓 테스트만 돌리지 않는다. 앞 티켓이 세운 규칙이 이번 변경으로 깨졌는지는 전체를 돌려야 보인다.
`--rerun-tasks` 없이 "통과"를 읽으면 캐시된 지난 결과일 수 있다.

### 2. 신고된 증상을 실측으로 다시 부른다

테스트가 초록인 것과 실제 서버가 그렇게 응답하는 것은 다르다.
1단계에서 증상을 재현했던 curl 을 **그대로** 다시 보내, 이제 기대 응답이 나오는지 본다.

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN      # 낡은 서버가 떠 있으면 판정이 거짓이 된다
./gradlew bootRun                      # 반드시 지금 코드로 다시 띄운다
```

회귀로 적은 규칙 중 최소 하나도 함께 부른다. 특히 경계값(허용되는 쪽 끝)을 부른다.

### 3. 바뀐 코드를 읽는다

- 인수 조건 밖의 동작을 함께 바꾸지 않았는가
- 이번 티켓에서 처리하지 않기로 한 것(`tickets.md` 의 발견 티켓)을 슬쩍 처리하지 않았는가
- 처리하며 새로 보인 것이 있으면 티켓으로 등록한다. **발견 경위**와 **무엇이 확인되면 정리되나**를 함께 적는다

## 남기는 것

- `docs/tickets.md` — 이 단계에서 새로 발견한 것이 있으면
- `docs/retrospective.md` — 이 티켓에서 **무엇을 겪었는가**. 다음 티켓에서 안 겪고 싶은 것만 적는다
  - 다시 찾아본 절차, 헛돈 자리, 판정이 거짓이 될 뻔한 자리
  - 절차로 굳힐 만한 것은 스킬로, 테스트 제약이면 `test-guide.md` 로 옮길 후보로 표시한다
- 커밋 — 위 문서 변경이 있을 때만

## 자기 점검

- [ ] `--rerun-tasks` 로 **전체** 테스트를 돌렸고 전부 통과하는가
- [ ] 신고된 증상을 지금 코드로 띄운 서버에 다시 불러 기대 응답을 받았는가
- [ ] 회귀 규칙 중 경계값을 실측으로 확인했는가
- [ ] 처리하지 않기로 한 티켓을 건드리지 않았는가
- [ ] 겪은 것을 `retrospective.md` 에 남겼는가

## 넘어가기 전에 사람이 확인할 것

- 요구사항대로 됐는가. 신고한 사람이 이 응답을 받으면 해결됐다고 볼 것인가
- 원래 되던 것이 안 깨졌는가
- 이번 티켓의 범위를 넘어선 변경이 섞이지 않았는가
- 회고에 적힌 것 중 지금 굳힐 것과 더 겪어봐야 할 것을 나눈다
