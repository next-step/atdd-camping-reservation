# ATDD 완료 판정

인수 조건과 실제 변경을 대조해 티켓이 끝났는지 근거로 판정한다. 검토 요청만으로 구현을 추가하거나 범위를 넓히지 않는다.

## 작업 전

1. 적용되는 저장소 지침과 대상 티켓의 범위를 확인한다.
2. 저장소에 있으면 `docs/principles.md`, `docs/plan.md`, 관련 `docs/acceptance-criteria.md`, `docs/test-guide.md`, `docs/tickets.md`를 읽는다.
3. 작업 트리와 diff를 확인해 대상 티켓의 변경과 기존 사용자 변경을 구분한다.
4. 인수 조건의 각 규칙을 관련 테스트와 구현 지점에 연결한다.

## 판정

- 대상 인수 테스트를 실행해 요구 동작을 확인한다.
- 저장소가 지정한 전체 테스트를 실행해 기존 동작의 회귀를 확인한다.
- diff를 읽어 실패 원인이 실제로 제거됐는지, 인수 조건이나 테스트를 약화하지 않았는지 확인한다.
- 유사한 코드 경로를 확인하고 현재 티켓에 적용되는 지점과 범위 밖 지점을 구분한다.
- 저장소가 직접 실측을 요구하면 변경 전과 같은 경계를 다시 호출한다. 변경 전 기록과 변경 후 결과를 구분한다.
- 테스트 통과만으로 저장 여부나 외부 응답을 증명할 수 없는 경우 필요한 추가 근거를 확인한다.

인수 조건이 충족되지 않았거나 근거가 부족하면 완료로 판정하지 않는다. 리뷰 중 발견한 범위 밖 문제는 후속 티켓 후보로 제시하고, 문서 변경은 사용자 요청이나 저장소 절차가 허용할 때만 수행한다.

## 완료 보고

다음을 근거와 함께 설명한다.

- **판정:** 완료 또는 미완료
- **인수 조건:** 각 규칙을 증명한 테스트나 실측
- **변경 범위:** 변경된 지점과 그 이유
- **범위 밖:** 확인했지만 변경하지 않은 유사 지점과 이유
- **회귀 확인:** 대상 테스트와 전체 테스트 결과
- **남은 일:** 부족한 근거, 후속 티켓, 추가 실측

커밋, 푸시 등 저장소 작업은 사용자가 명시적으로 요청했을 때만 수행한다.
